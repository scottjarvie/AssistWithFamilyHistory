# AI-readiness audit — Assist With Family History — 2026-11-24

Audited at `main` `708a0dd`. Findings only: no product code, docs or config were changed.
Nothing was installed, built or run; evidence is file:line read in a fresh clone.

## Summary

1. The rules in `AGENTS.md` are accurate, and every path and link in it resolves. The trouble is the older documents around it.
2. Four Convex guides still listed as current tell an AI to run `npx convex deploy --prod` and call functions that no longer exist; the README describes the product as it was in May.
3. About 2,900 lines of backend code and about 500 lines of screen code have no caller at all, and 5,600 lines of frozen "before" design copies sit in the same folder as live components.
4. The local check is thorough (57 steps), but it never type-checks or lints its own 113 scripts or the 53 backend test files, and four test files are run by nothing.
5. Six backend files are 1,300 to 2,800 lines, and many newer files pack 300 to 4,000 characters on a line, which makes AI edits and reviews error-prone.

## How the project is shaped

A Next.js 16 site (`app/`, 43 API routes) on a Convex backend (`convex/`, 57 tables) with Clerk sign-in. Signed-in pages live under `app/app/*`; public pages (home, stories, `/ai.txt`, `/updates`) sit beside them. Pages read through `convex/vaultReads.ts` (public actions that check the owner) which call internal queries in `convex/vault.ts`; writes go through `convex/vaultMutations.ts` and the builders in `convex/searchServer.ts`, which keep search rows and counters in step. The "Bring your AI" connector is `convex/httpRoutes/mcp.ts` (transport and tool list) over `convex/mcpFamilyHistory.ts` (tool behaviour), `convex/mcpGrants.ts` (who may do what) and `lib/mcp/`. Media evidence goes to private B2 storage through `convex/mediaEvidence*.ts` and `lib/media/`. `components/` holds screens by area (`vault/`, `queue/`, `ai/`, `marketing/`), `extension/` is the Chrome capture extension, `scripts/` holds the 48 contract checks behind `pnpm verify`, and `docs/tracker/` is the Card tracker. Product truth is `docs/planning/site-guide.md`.

## Findings

### 1. Convex guides listed as current tell an AI to deploy production by hand
- Evidence: `docs/deployment/convex-checklist.md:26,210,261` (`npx convex dev`, `npx convex deploy --prod`); `docs/convex/nextjs-integration.md:64,115,408,412`; `docs/convex/quick-reference.md:231-236` (`api.persons.get`, `api.helpers.createPersonWithBirth`). Linked as current from `docs/README.md:49-52` and `convex/README.md:7-10`.
- Why it matters: `AGENTS.md:39-41` forbids exactly these commands, and the functions shown are no longer callable from a page, so an AI that follows the folder's own README is led wrong twice.
- Fix: move the four files to `docs/archive/`, and point `convex/README.md` at `docs/operations/how-production-deploys.md` plus a ten-line note on the `vaultReads` → `vault` → `vaultMutations` layering.
- Size: small. Label: **safe to fix**.

### 3. Seven early backend files are no longer called by anything
- Evidence: `convex/helpers.ts` (569 lines), `convex/events.ts` (288), `convex/sources.ts` (167), `convex/personEvents.ts` (85), `convex/media.ts` (76): zero references. `convex/persons.ts` (561): one reference, a test (`convex/personHistory.test.ts:134` calls `internal.persons.remove`). `convex/relationships.ts` (432): only the two pure helpers `buildAncestors` and `buildDescendants` are used, by `scripts/test-family-tree.ts:19-24`.
- Proof: searched every tracked file outside `convex/_generated` for `api.<module>.`, `internal.<module>.`, `"<module>:<name>"` string references and imports of each file; `convex/crons.ts:4` schedules one unrelated function; `convex/http.ts:1-9` registers only the connector and upload routes. All are internal functions (`convex/persons.ts:3`), so no browser can call them.
- Why it matters: these 2,200 lines look like the main people, events and sources code, so an AI asked to change how people are saved will find them first and edit code nothing runs.
- Fix: delete the five unreferenced files; move the two tree helpers out of `relationships.ts` into a small `lib/` file and delete the rest; keep `persons.remove` only if person deletion still needs it (the test is its only caller).
- Size: medium. Label: **safe to fix, except** the `familySearchSync` table in `convex/schema.ts:1348` (only `helpers.ts:507-540` touches it; dropping a table is a schema change that **needs Scott**) and **a production check** that nobody runs these functions by hand from the Convex dashboard.

### 6. Scripts that cannot run, and two checks that never run

### 7. The local check never type-checks or lints its own scripts and tests
- Evidence: `tsconfig.json:53-54` excludes `scripts` and `convex/**/*.test.ts`; `convex/tsconfig.json:24` excludes the tests again; `eslint.config.mjs:16` ignores `scripts/**`. The scripts run through `tsx` and the tests through Vitest, and neither checks types.
- Why it matters: the 48 contract checks and 53 backend tests are the safety net, and a renamed field or function in them shows up only as a runtime failure, or as a check that quietly asserts on nothing.
- Fix: add a `tsconfig.checks.json` covering `scripts/` and the test files, and one `typecheck:checks` step in `scripts/verify.sh`. No new CI workflow is needed; CI already runs `pnpm verify`.
- Size: medium (expect some type errors to clear first). Label: **safe to fix**.

### 8. Four test files are run by nothing, and one list has drifted
- Evidence: `scripts/test-record-only-snapshot.ts` and `scripts/local-development.test.mjs` are not in `pnpm test` (`package.json:11`); the tracker already records that the first fails on a clean checkout (`docs/tracker/cards/AWF-0077.md:119-125`). `tests/e2e/ai-connection-reapproval.spec.ts` and `tests/e2e/home-drawn.spec.ts` have no script and there is no Playwright config; only the tracker spec is wired (`package.json:30`). `test:coverage` (`package.json:13`) omits five files that `test` runs.
- Why it matters: an AI sees a test beside the code and assumes the behaviour is protected; the AI-connection re-approval flow in particular has a browser test that nothing ever starts.
- Fix: do the AWF-0077 port; add `test:e2e` as a manual script and name it in `docs/operations/product-health-gates.md`; build `test:coverage` from the same list as `test`.
- Size: small. Label: **safe to fix**.

### 9. Many newer files pack hundreds of characters on a line
- Evidence (measured by script): `app/design-council-preview/page.tsx` 98 lines, 19 KB, longest line 3,982 characters; `convex/personScores.ts` 151 lines, 17 KB, longest 1,088; `components/collections/CollectionWorkspace.tsx` 131 lines, 22 KB; `components/queue/QueueWorkspace.tsx` 742 lines, 48 KB, longest 1,110; `components/audit/AuditWorkspace.tsx` 117 lines, 20 KB; `convex/placePages.ts` 135 lines, 15 KB. 25 source files have eight or more lines over 300 characters. The repo has no formatter configured.
- Why it matters: AI edits work by matching exact text and reviews work by reading diffs; a one-word change on a 1,000-character line is easy to misplace and almost impossible to review.
- Fix: one formatting-only pull request that adds Prettier with default settings and reformats `app/`, `components/`, `convex/` and `lib/`; no behaviour change.
- Size: medium. Label: **safe to fix**.
