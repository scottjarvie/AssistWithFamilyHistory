## Ranked findings

### 1. C01 · Guest transfer still lacks backend proof of source ownership

**Defensive safety · needs Scott · medium**

- **Evidence** The public mutation authenticates the destination. Source verification goes through a policy helper that logs and returns in shadow mode. The website route reads the guest cookie, but Convex independently receives only the owner identifiers. [convex/vaultMigration.ts:152](../../../convex/vaultMigration.ts#L152), [convex/access.ts:142](../../../convex/access.ts#L142), [app/api/vault/migrate-guest/route.ts:42](../../../app/api/vault/migrate-guest/route.ts#L42), [docs/operations/gen-87-clerk-convex-auth-setup.md:107](../../../docs/operations/gen-87-clerk-convex-auth-setup.md#L107)
- **Impact** Where shadow mode and legacy guest records coexist, the backend does not establish authority over the records it will transfer.
- **Fix** Decide whether to retain guest recovery using verified source proof or retire this transfer path. Keep the destination check and record the disposition in the rollout runbook.
- **Expected gain** Zero transfers without verified source authority in either mode.

### 2. C02 · The legacy owner file action returns a permanent storage address

**Defensive safety · safe to fix · medium**

- **Evidence** The owner action returns the Convex storage URL received from the internal query. The normal Next file route relays bytes, but the public Convex action itself still returns the provider address to its authenticated caller. [convex/vaultReads.ts:97](../../../convex/vaultReads.ts#L97), [convex/vault.ts:1699](../../../convex/vault.ts#L1699), [app/api/media/[mediaId]/file/route.ts:38](../../../app/api/media/%5BmediaId%5D/file/route.ts#L38)
- **Impact** An address issued for a legacy file can outlive the owner's session and later changes to access.
- **Fix** Stream authorized legacy bytes through first-party delivery and keep the provider address server-side. Preserve range, MIME and not-found behavior. Treat remediation of old addresses as a separate owner decision.
- **Expected gain** Zero newly issued permanent storage addresses from this action.

### 3. C03 · Regular MCP evidence reads can deliver exact recordings inline

**Defensive safety and correctness · safe to fix · medium**

- **Evidence** The regular batch treats an eligible B2 recording as an original slot and an eligible older Convex recording as a non-image file. Delivery emits those exact bytes as resource content. The tool catalog and family standard put exact recordings on the explicit one-minute original path. - **Expected gain** Zero exact recording bytes in regular MCP evidence replies. Each authorized original link has a lifetime of at most 60 seconds.

### 5. C05 · D2 cleaned copies cover only one class of original-only photo

**Correctness and media · safe to fix · medium**

- **Evidence** The website Convex-original renderer accepts a MIME allowlist and rejects multi-page images or sources above 32 million pixels.
