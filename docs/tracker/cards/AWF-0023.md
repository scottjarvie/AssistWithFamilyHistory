## Why this exists

A complete research vault must let a person find a name variant, place, source,
claim, event, note, memory, research question, or story without knowing which
screen owns it, while keeping result type and evidence status visible.

## Current truth

People and places have narrow search, operations has filters, stories and
documents have route-specific reads, and context packs support person-centered
retrieval. No universal owner-scoped search route, result contract, relevance
model, privacy filter, or cross-object navigation is verified.

## Scope

- Search the durable Family History object model with explicit result type,
  subject, source/provenance, confidence/review state, and safe snippet.
- Keep private, AI-eligible, collaborator-visible, Unlisted, and Public
  visibility separate in backend filtering.
- Use bounded indexed retrieval, deterministic continuation, useful empty and
  typo states, and route back to the authoritative record.

## Next safe action

Inventory searchable fields and privacy classes, then prototype against
synthetic fixtures after scalable list/query contracts are established.

## Unknowns and access limits

Index technology, scale, ranking expectations, language handling, and private
snippet risks need design. No production vault corpus may be used for testing.

## Evidence

Acceptance evidence includes cross-object fixtures, visibility denials,
provenance snippets, typo/variant scenarios, index/query budgets, pagination,
and phone/desktop keyboard navigation.

## Definition of done

- [ ] Search spans the agreed durable object set without flattening object types.
- [ ] Every result shows why it matched and its provenance/review state.
- [ ] Visibility is enforced at the backend for every access mode.
- [ ] Results are bounded, indexed, paginated, and route to authoritative records.
- [ ] Empty, typo, variant-name, date, place, and source scenarios work.
- [ ] Security, performance, PR/CI/deployment, and independent audit proof exist.
