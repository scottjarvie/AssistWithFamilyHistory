## Why this exists

A person must be able to delete a photo or scan and know every copy is gone.
There is currently no media deletion at all, and replacing a file on a B2 record
keeps serving the old copy.

## Current truth

`deleting` state is defined but never set; only expired upload sessions are
cleaned. `attachMediaFile` sets `storageId` but leaves `mediaState: ready` and the
B2 renditions (`convex/vault.ts`, `convex/vaultMutations.ts`).

## Scope

- Delete action: deleting state gates every byte path; remove every version of
  the original and all display sizes; retryable pending-cleanup record.
- Replacement retires the old B2 object and renditions.
- Hooks for account deletion (AWF-0010).

## Next safe action

Write the failing test for replacement serving the old copy.

## Evidence

- 2026-10-06: Recorded from the read-only 6 October audits summarized in [the Site Guide](../../planning/site-guide.md#where-family-history-stands-6-october-2026). No application, provider or account change.

## Definition of done

- [ ] Deleting a file removes every B2 version and rendition, proved by re-query.
- [ ] Replacing a file serves the new file and cleans up the old.
