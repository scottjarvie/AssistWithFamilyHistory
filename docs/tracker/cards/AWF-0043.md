## Why this exists

Source compatibility and a successful tool list are not the product promise. A
person needs proof that one real compatible AI can accept narrow authority, do
source-aware work, return a reviewable result, lose access when disconnected,
recover after reconnect, and leave no synthetic residue.

## Current truth

One disposable public PKCE client previously proved explicit provider consent,
official-client tool discovery, complete saves, correction, UI reflection, and
exact cleanup in an empty test vault. AWF-WO-009 later delivered the joined
Queue/result-link source and production release, but its final authenticated
Queue round trip was blocked by the available browser hosts.

No run has proved CIMD-first onboarding, product scopes, active grant creation,
protected evidence retrieval, review-first save, immediate revoke denial,
reconnect/stale-tool recovery, or a named production client. The intended
clients—Claude, ChatGPT, Codex, Grok, Hermes, and other conforming clients—remain
capability targets only.

## Requirements

- Use a marked isolated identity/workspace and build exact cleanup before the
  first live mutation.
- Prove discovery/registration, PKCE sign-in, exact consent, active grant, tool
  scope behavior, Queue assignment, brief, evidence, result save, correction,
  normal UI visibility, and activity.
- Prove out-of-scope, cross-owner, stale version, replay conflict, malformed
  metadata, expired grant, and revoked grant denial.
- Revoke and show immediate denial, then reconnect and verify fresh tool state.
- Delete fixtures, grants, registrations, sessions, token artifacts, clients,
  receipts, and marked activity; re-query for zero residue.
- Record exact client name/version and lifecycle evidence before adding that
  name to `/ai` or release notes.

## Next safe action
