## Why this exists

Source compatibility and a successful tool list are not the product promise. A
person needs proof that one real compatible AI can accept narrow authority, do
source-aware work, return a reviewable result, lose access when disconnected,
recover after reconnect, and leave no synthetic residue.

official-client tool discovery, complete saves, correction, UI reflection, and
exact cleanup in an empty test vault. AWF-WO-009 later delivered the joined

## Current truth — 2026-08-16 (Claude, execution)

The ladder is now a runnable harness rather than a written procedure.
`pnpm mcp:lifecycle` (`scripts/mcp-lifecycle.ts`) walks all eleven points
against a configurable endpoint as a real MCP client, printing a pass/fail line
per step and a machine-readable JSON summary. It refuses to start unless the run
key matches the acceptance prefix, reads its token from the environment only,
never prints it, and pauses for the person at the two points that are genuinely
human acts — approving and revoking a connection.

Eight of the eleven rungs are additionally proved locally, with the same official
client and the same protocol pin, in `convex/mcpLifecycleLadder.test.ts`:
anonymous challenge, branded metadata, grant-filtered and empty discovery,
out-of-scope refusal without leakage, batch save with correction and stale-write
refusal, indistinguishable unknown/ungranted/invented/cross-owner refusals,
`operationId` replay, and revocation denying the very next call on a still-valid
token.

Writing the harness found two real interoperability defects that source review
had not: the empty tool catalog and the preflight refusal were both written
straight onto the wire without protocol revision 2026-07-28's required
`resultType`, so a conforming client rejected them as malformed — meaning the
carefully written "ask the person to approve this" message never reached a real
AI. `observedClientName` was also reading the `Mcp-Name` header, which carries
the tool being called, so a person's connection would have been labelled
something like `save_person`. Both are fixed and both are now guarded by
`scripts/check-mcp-contract.ts`.

`convex/mcpAcceptanceFixture.ts` now covers `mcpGrants`,
`mcpClientRegistrations`, and grant-linked `agentActivity` rows, keeping its
exact safety posture: bounded scans, visible synthetic markers, and a refusal
when anything unmarked references the marked graph.
