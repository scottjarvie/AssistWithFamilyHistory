## Why this exists

The soft-launch rebrand made the product and sign-in coherent, but a retained
empty test identity still landed on a dashboard whose primary actions were
Story Studio and the Research Queue. With zero people, sources, stories,
imports, or tasks, those actions do not explain how to begin. The app
navigation also labeled a legacy API-key console as **AI access**, even though
the current supported chosen-AI path is OAuth MCP at `/ai`.

## Current truth

A production first-journey audit at 390 pixels reproduced the mismatch without
accessing or creating any family records. Signed-out `/app` reached the branded
Clerk form with the correct return target and no console errors. The retained
non-privileged identity reached an empty private workspace and an empty Queue.
Queue's four states and no-autonomous-runner boundary were clear, but its MCP
message had no setup link. The signed-in **Your AI → AI access** navigation led
to `/app/api`, where the page described key verification as rolling out and
raised a React hydration error. Public `/ai` was responsive, accurate, and free
of console errors.

The bounded repair detects the genuinely empty dashboard and replaces
downstream work actions with two current starts: bring in a reviewed capture or
connect a chosen AI through OAuth MCP. It gives a short privacy/authority
boundary, links Queue's MCP message to setup, and makes signed-in **Your AI**
navigation point to **Connect your AI** at `/ai`. The legacy key console remains
available by direct URL for compatibility, but now names OAuth MCP as the normal
path and no longer renders `window.location` during server output.

Version 2.0.1 is Public & live. Protected PR #45, exact-main CI, the normal
Vercel production deployment, signed-out sign-in, isolated signed-in mobile and
desktop acceptance, Queue-to-setup navigation, the legacy compatibility route,
public AI docs, and the anonymous MCP challenge all passed. The retained test
identity is empty and again has zero active sessions.

## Strongest next improvement

The philosophy's friendliest start—add one person and a known relationship
without an import or AI connection—is still not a current ordinary-user flow.
That is the strongest next product improvement after this repair. It needs its
own bounded design and persistence tranche; this release must not imply that
manual entry exists.

## Boundaries

- Use only the retained empty non-privileged identity and safe signed-out checks.
- Do not create family records, directives, API keys, OAuth clients, or provider
  settings for this audit.
- Do not access Scott's account or another family's workspace.
- Keep the legacy API-key surface directly reachable until its compatibility and
  administrative users receive a separate deprecation decision.
- Preserve the exact four Queue states and the rule that nothing runs
  automatically.
