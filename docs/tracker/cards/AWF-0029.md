## Why this exists

The durable Queue backend should become a clear, archival Family History
experience without letting backend implementation pre-decide page composition,
card layout, navigation, or visual language.

## Current truth

The Queue foundation and P0 authority repair define exact states, commands,
actor/handoff meaning, optional context, service conditions, pagination,
activity, deletion, and API seams in
`docs/product/queue-foundation-design-handoff.md`. Scott approved AWF-WO-005.
An isolated Clerk development proof exercised the product-native `/app/queue`
route and navigation against the configured development Convex target. The
screen now implements the exact four states, bounded list/detail and activity
reads, person-side lifecycle actions, honest disconnected-AI copy, and complete
loading/empty/error/permission treatments. Desktop and narrow-phone visual

`EwU4tNWp2P6aMoGHgq4M2iKwZr79` passed. Both preview and production deployment
URLs stop at Vercel login before the app, so public production UI proof is not
claimed.

A separate 2026-08-12 acceptance pass against current main `6e346cb` repeated
the authenticated development journey with two new disposable Clerk test
identities and the configured development Convex deployment. One marked item
proved all four browser-visible states, person claim/checkpoint/result,

remain isolated in AWF-0030.
