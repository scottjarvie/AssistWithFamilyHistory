## Why this exists

The durable Queue backend should become a clear, archival Family History
experience without letting backend implementation pre-decide page composition,
card layout, navigation, or visual language.

## Current truth

The Queue foundation defines exact states, commands, actor/handoff meaning,
optional context, service conditions, pagination, activity, deletion, and API
seams in `docs/product/queue-foundation-design-handoff.md`. No final `/queue`
page, navigation entry, responsive interaction, or authenticated designed
journey is implemented or claimed.

## Scope

- Use Claude Design to define the final screen, card/detail relationship,
  responsive information hierarchy, and Family History visual treatment.
- Exercise directive-only create, optional context, Needs You answer, Working
  step, Waiting truth, Done result/history, filters/pagination, human-only use,
  retry/conflict, disconnected, expired, permission, empty, loading, and error.
- Preserve the existing Discover Their Stories shell and research-to-story
  vocabulary; do not copy another Assist product's palette or page composition.
- Add navigation only after the complete route is functional and truthful.

## Next safe action

Give Claude Design the Queue foundation handoff and representative existing
signed-in seams. Return an implementable design contract, then use a separate
Ready Work Order and normal software safeguards.

## Unknowns and access limits

Authenticated production styling, final mobile navigation placement, and live
Queue data shape after deployment are unverified. Use synthetic private-safe
fixtures; do not inspect a real family vault.

## Evidence

Acceptance evidence includes final design rationale, implemented desktop/phone
flows, keyboard/screen-reader states, reduced motion, no page overflow, exact
state/condition truth, conflict/retry behavior, console/network checks, full CI,
deployment, and authenticated synthetic proof.

## Definition of done

- [ ] Claude Design handoff is accepted without changing backend semantics.
- [ ] Complete Queue interaction works on desktop and narrow phone widths.
- [ ] All state, condition, service, empty, and error treatments are truthful.
- [ ] Human-only operation works and chosen-AI availability is never invented.
- [ ] Activity, result, context, and deletion remain understandable and safe.
- [ ] PR/full CI/deployment/authenticated proof and independent audit exist.
