## Why this exists

Operation Cleanup, Stage 4. One grouped card for the AI-connection work still
wanted. It replaces AWF-0022, AWF-0043, AWF-0050, AWF-0063 and AWF-0064, and
carries the named-client run left from AWF-0038, all closed on 2026-11-06.
Already live: stateless `/mcp`, Clerk DCR, durable grants re-checked on every
call, sign-in as the approval (AWF-0062), and `pnpm mcp:lifecycle`.

## Current truth

- **No named AI client has run the full lifecycle** (from AWF-0043, AWF-0038).
  Only a disposable PKCE client was proven (August 2026). Run
  `pnpm mcp:lifecycle` (`scripts/mcp-lifecycle.ts`) against production with one
  real client (Claude, ChatGPT or Codex) and record its JSON summary; promote
  only what that client actually showed.
- **Standard 1.3.0 conformance gaps** (from AWF-0063). `www.` machine paths
  redirect instead of answering; `scopes_supported` omitted so `offline_access`
  is never advertised (`convex/httpRoutes/mcp.ts:98-119`); identity-provider
  outages return 401 instead of 503; tools capability missing when the list is
  empty; `/llms.txt` hand-written and stale; `/ai` lacks per-client steps.
- **One frozen operation contract** (from AWF-0050, AWF-0022). Input schemas
  live in the transport, descriptions and scopes in the catalog; no versioned
  inventory of request, response, errors and replay; no `outputSchema`; no
  `openWorldHint: false`. Freeze the existing tools first, without adding tools
  or widening permissions. There is no public HTTP API, SDK or CLI, and none
  should be built to fill a matrix.
- **Tools for every building block** (from AWF-0064). Search needs typed text
  and has no cursor; one record per read; no place, topic, question, list,
  Library, Queue-add or Suggestions tools. Design the catalogue against the Site
  Guide blocks (AWF-0086) before adding tools.
