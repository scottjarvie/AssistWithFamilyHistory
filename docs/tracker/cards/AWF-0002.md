## Why this exists

Cards and Project Philosophy state should travel quickly without paying for a
full application test and production build, while every software, workflow,
validator, dependency, schema, or configuration change keeps normal safeguards.

## Current truth

Before this rollout, GitHub ran the full CI job for every push, Vercel built
every `main` commit, and `main` had no protection or ruleset. PR #28 installed
one shared exact allowlist, local commit helper, strict push classifier,
zero-dependency validators, and a full-range Vercel ignored-build classifier.
State commit `dc304294f4213ff3eb29f64e632c310c108acbd6` then proved the
trusted-owner lane at GitHub, Vercel, and the retained production alias.

## Next safe action

For routine tracker or canonical Project Philosophy state, fetch `main`, stage
only the exact allowlist, run `pnpm tracker:commit-state --check`, commit with
the helper, and push `HEAD:main`. Any software, config, workflow, validator,
schema, dependency, mixed, renamed, malformed, or uncertain change uses PR,
full CI, and normal deployment.

## Constraints

- The exact changed-file range controls classification, not intent alone.
- Direct-main publication is owner-only and state-only.
- Missing history, malformed SHA, rename, mixed path, failed validator, or any
  uncertainty must build normally.
- GitHub Actions, Vercel deployment state, and live production alias identity
  are separate evidence gates.
