## Why this exists

A researcher must be able to see what changed, who or which chosen AI did it,
why, and how to inspect the affected evidence.

## Current truth

Import runs, research logs, story review events, source links, model/prompt
fields, and an append-only `agentActivity` schema are partial foundations.
Source does not prove one plain-language, record-visible entry for every
meaningful create, change, delete, merge, publish, denial, or external-AI action.

## Scope

- Define meaningful events and actor vocabulary.
- Show affected object, source, operation, outcome, time, scope, review state,
  and safe detail from both the record and account.
- Cover human UI, first-party AI, chosen-AI key/MCP, import, merge, and publish
  paths with consistent semantics and bounded retention.
- Never store secrets or raw private payloads in activity logs.

## Next safe action

Map current event writers and missing mutations before changing schema. Reuse
existing append-only records where their semantics match.

## Unknowns and access limits

Production log destination, retention, usage UI, and mutation coverage are
unverified. Evidence must use synthetic, redacted records.

## Evidence

Acceptance evidence includes an event coverage matrix, mutation fixtures,
actor/scope tests, record and account browser views, retention/redaction tests,
and one inspectable chosen-AI round trip.

## Definition of done

- [ ] Every defined meaningful operation emits one safe, attributable event.
- [ ] Users can inspect activity from the affected record and account view.
- [ ] Events distinguish user, first-party AI, chosen AI, and system work.
- [ ] Denied/error events help without leaking payloads or secrets.
- [ ] Retention, export, and deletion policy for activity is explicit.
- [ ] Schema, PR/CI/deployment, live proof, and independent audit exist.
