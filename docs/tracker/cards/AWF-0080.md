## Why this exists

Operation Cleanup, Stage 3. PR #89 is being closed; this card keeps its idea.

## What it does

- Tenant checks enforce caller identity by default. Today
  `getTrustBoundaryMode` returns `shadow` unless `TRUST_BOUNDARY_MODE` is exactly
  `enforce` (`convex/access.ts:34-36`), and both production settings are unset.
- MCP brief, search and writes stay inside a selected-people grant, including
  records reached through create keys, batch aliases and old operation
  receipts. This fixes FH-R006 (AWF-0076).

## Why still worth doing

The selected-people grant is a promise on the AI page; FH-R006 shows it does
not hold for brief and search. Fail-open tenant checks are the wrong default
before a second person ever signs in.

## Why it was parked

- It changes the auth default for the whole backend.
- The required shadow-mode-first trial never ran; the PR itself lists unproven
  items (production JWT template, issuer/audience parity, owner-bound transport,
  historical guest migration).
- The site has one owner today, so there is no cross-user exposure yet.

## Decisions for Scott

1. **Make a leaked AI access token killable, not just useless** (from AWF-0034).
   Revoking a connection already stops access at once, because the grant is
   re-checked on every `/mcp` call. A leaked Clerk JWT still cannot be revoked
   at the provider. Recommendation: a short design spike on Clerk opaque access
   tokens; if they break stateless clients or add latency, a small server-side
   revocation list keyed by client. Safe default: leave as is (defence in depth
   only).
