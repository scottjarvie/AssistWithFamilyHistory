## Why this exists

Tool names, descriptions, required permissions, aliases, and consent language
come from `lib/mcp/catalog.ts`, but the actual Zod input schemas are registered
inside `convex/httpRoutes/mcp.ts`. Response shapes, backing operations, error
codes, batch behavior, provenance, receipts, and replay rules are distributed
across handlers and tests. A catalog change can therefore look internally
consistent while changing the wire contract or recovery behavior.

## Current truth

The current release has sixteen canonical tools, twelve compatibility aliases,
and seven person-approved permissions. Batch saves retain successful rows and
return per-item failures; callers retry only failed rows with a new top-level
operation id. Create keys and command receipts prevent duplicate mutations.
Public and machine truth now fail verification when tool names or authority
tiers drift, but there is no version/fingerprint for the complete operation
contract and no generated comparison of request/response/error behavior.

There is no stable public HTTP API, SDK, or CLI. Contract parity must describe
those surfaces as absent; it must not create them merely to make a checklist
look complete.

## Bounded scope

- Inventory exactly the sixteen existing canonical tools and their retained
  aliases.
- For each tool, record backing Convex operation, read/write posture, required
  and conditional permission, record boundary, request schema, result shape,
  batch limits, operation-id/create-key behavior, provenance, errors and caller
  recovery, reversibility, human confirmation, and current proof.
- Give the inventory a deterministic version or fingerprint and fail checks
  when transport registration, handlers, `/ai`, `/ai.txt`, the capability
  manifest, or lifecycle harness diverge from it.
- Preserve current default/person-approved/reserved authority and every privacy,
  living-person, review, rights, and owner boundary.

## Exclusions

- No new MCP tool, generic CRUD API, OpenAPI claim, SDK, CLI, permission,
  raised-authority path, admin/delete/publish/merge/share/external-provider
  operation, or alias removal.
- No Backblaze credential, provider setting, production data, or named-client
  mutation.

## Definition of done

- [ ] Every existing tool has one reviewable operation-contract entry.
- [ ] Generated or structural checks catch schema, response, error, replay,
      alias, permission, public-guide, and machine-manifest drift.
- [ ] Batch partial success and retry semantics remain explicit and tested.
- [ ] Absent API/SDK/CLI surfaces are reported as absent, not implied.
- [ ] Full verification, protected PR, exact-main CI/deploy, live machine-path
      proof, and independent audit remain separate evidence layers.

## Evidence

- 2026-09-03 source audit: catalog names/descriptions/scopes live in
  `lib/mcp/catalog.ts`; Zod inputs and registrations live in
  `convex/httpRoutes/mcp.ts`; responses/errors/replay are distributed through
  handlers and tests.
- The current branch proves name, permission, public-guide, and machine-manifest
  parity only. It deliberately does not claim complete operation-contract
  parity before the proposed Work Order is approved and executed.
