## Why this exists

Source, tests, full CI, Vercel builds, the live alias, and signed-out route
protection are proven. They do not prove that the production Convex build took
the deploy-key branch or that a real authenticated Queue round trip persists
with the expected tenant boundary.

## Verified current truth

PR #31 merged the original Queue source as `e65b03a`. The P0 tenancy and expiry
repair later merged through PR #32 as
`1a82a03ed207c8cd3c9e99f0dd4b6d4720c282cd`; exact-main Actions run
`31615964828` passed and Vercel production deployment
`HDzMFmbrsany1z95y6y63r3vSHgb` reported Ready and Current for that commit. A

cross-tenant production fixture, or exact Convex provider build-plan line was
available.

PR #34 later shipped the product-native Queue as protected main commit
`e4d1e35`. Exact-main CI run `31634382959` passed every verify and route-smoke
step, and Vercel production deployment `EwU4tNWp2P6aMoGHgq4M2iKwZr79`
completed. A fresh browser request to the exact production deployment and the
PR preview both redirected to Vercel login before Discover Their Stories or
Clerk loaded. That is verified deployment-protection behavior, not public Queue
or production-authenticated proof.

On 2026-08-12 a separate acceptance pass rechecked current main `6e346cb`, PR

current evidence that the public alias is not serving the released Queue route;
it does not contradict the successful protected deployment or authorize an
alias, promotion, or Deployment Protection change.

  enables a later public Clerk/Queue check.

  public behavior or authorize production test data.
