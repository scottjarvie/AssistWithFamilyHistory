## Why this exists

A person needs one place to understand their account, vault footprint, current
work, AI connections, sharing, and data controls.

## Current truth

Production `/me` returns 404. Settings, dashboard counts, API key management,
and route-specific activity exist, but no ordinary account surface combines
identity, storage, Queue/activity, AI footprint, sharing, and data controls.

## Scope

- Show site identity, safe counts, storage, Queue/activity, AI/key status,
  active sharing, and links to export/deletion/support.
- Provide clear empty, loading, error, and session-expired states.
- Keep site-specific identity language and keep `/me` separate from `/admin`.
- Do not reproduce private record content in account summaries.

## Next safe action

Define the minimum account DTO from existing bounded count queries; add missing
data only after its lifecycle Card provides authoritative state.

## Unknowns and access limits

Storage metering, Queue totals, connected-AI status, and sharing inventory are
partial or absent. Production user data was not inspected.

## Evidence

Acceptance evidence includes synthetic account states, query bounds, identity
and privacy review, phone/desktop UI, working control links, and cross-owner denial.

## Definition of done

- [ ] `/me` gives an ordinary user a useful, private account summary.
- [ ] Counts are bounded, owner-scoped, and reveal no record content.
- [ ] AI, sharing, activity, support, export, and deletion links reflect real state.
- [ ] Empty, error, session-expired, desktop, and phone states work.
- [ ] `/me` and `/admin` roles and data remain separate.
- [ ] PR/CI/deployment, authenticated proof, and independent audit exist.
