## Why this exists

Research questions and unfinished work need durable continuity between a person
and their chosen AI. The current research-operations console is useful, but it
is a derived readiness queue rather than the Core product Queue.

## Current truth

`/app/operations`, research tasks/checks/logs, context packs, and handoff JSON
are real repository foundations. There is no `/queue`, directive-first create
path, arbitrary chosen-AI pickup/return path, or exact Needs you / Working /
Waiting for your AI / Done state model. Existing database statuses and research
readiness labels must not be relabeled as the product Queue.

## Scope

- Add `/queue` with exactly the four Core states and Family History language.
- Make a plain directive sufficient; offer optional context in three groups:
  research subject, evidence, and work thread.
- Preserve scope, evidence, responsible actor, blockers, result, history, and
  one clear next step across handoffs.
- Enforce bounded directive authority; merges, disputed promotion, publication,
  destructive work, and access changes return to Needs you.
- Keep the product Queue distinct from the repository build tracker.

## Next safe action

Write a Queue domain contract and migration plan that reuses research-operation
records only where their semantics genuinely match. Use normal schema, PR, CI,
and deployment safeguards.

## Unknowns and access limits

- The durable Queue record shape, lease/retry model, and incoming chosen-AI
  credential path are not implemented.
- Do not expose private evidence or infer authority from an attached context id.

## Evidence

Acceptance evidence uses contract fixtures and browser scenarios proving create, pick up, checkpoint,
block, return, complete, stale recovery, and human-gate behavior with explicit
actor and scope history.

## Definition of done

- [ ] `/queue` uses exactly the four Core states and no research-status aliases.
- [ ] Directive-only creation works; context remains optional and grouped correctly.
- [ ] Handoffs preserve evidence, authority, blocker, result, and next action.
- [ ] Destructive, identity, access, and publish actions fail into Needs you.
- [ ] Human-only operation remains complete without an AI connection.
- [ ] Schema migration, PR, CI, deployment, authenticated browser proof, and independent audit exist.
