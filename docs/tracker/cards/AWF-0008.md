## Why this exists

Research questions and unfinished work need durable continuity between a person
and their chosen AI. The current research-operations console is useful, but it
is a derived readiness queue rather than the Core product Queue.

## Current truth

The implementation branch now has a distinct `queueItems` model, append-only
Queue activity, idempotency receipts, directive-first creation, exactly four
product states, bounded indexed pagination, version/lease concurrency,
retry/failure/cancel/expiry semantics, owner-verified context adapters, hard
deletion, internal APIs, and a narrow chosen-AI tool contract. Existing
research tasks/checks, imports, story status, and `/app/operations` remain
separate. Deployment, authenticated production behavior, incoming chosen-AI
credentials, and the final designed `/queue` experience are not yet proven.

## Scope

- Implement the durable Queue model, commands, activity, query/pagination,
  authorization, deletion, and domain context adapters.
- Prove directive-only, exact-state, tenancy, transition, retry/failure,
  concurrency, idempotency, activity, human-only, and narrow agent scenarios.
- Provide only design-independent APIs and the exact Claude Design handoff.
- Keep research operations, domain statuses, and the build tracker distinct.
- Publish through normal PR/full CI/schema/deployment safeguards.

## Next safe action

Finish full verification and publish the source/schema through the normal
protected PR, CI, Convex/Vercel deployment, and live proof path. Do not backfill
existing records: no source proves they began as user Queue directives.

## Unknowns and access limits

- Incoming chosen-AI credential resolution, live MCP, final Queue UI, deployed
  schema, authenticated production behavior, and independent audit remain
  unverified.
- Do not expose private evidence or infer domain authority from context ids.

## Evidence

Acceptance evidence uses pure and real Convex-runtime fixtures proving create,
assign, pick up, checkpoint, block/resume, retry/exhaustion, complete,
cancel/reopen, expiry, stale-version rejection, idempotent replay, owner
isolation, foreign-context denial, hard deletion, human-only use, and narrow
agent scope. PR/CI/schema/deployment/live receipts remain required.
