## Why this exists

A person should not have to understand OAuth plumbing to know which AI can see
which family material, what it may change, when it last worked, and how to stop
it. The connection experience is part of the privacy product, not merely setup
documentation.

## Current truth

`/ai` and `/ai.txt` provide the branded endpoint, compatible-client capability
requirement, first call, twelve-tool catalog, one-call save guidance, safety,
stale-tool recovery, and Current/Partial/Later truth. They do not expose a
client-specific setup recipe without proof, which is correct.

There is no authenticated `/settings/ai` connection center, scope picker,
record-boundary selector, connected-client list, last use, safe activity,
expiry, or immediate revoke control. The older API-key management UI is a
separate credential system and does not prove OAuth connection management.

## Requirements

- Keep `/ai` calm, outcome-first, client-neutral, and truthful.
- Add an authenticated connection center using the app's signed-in navigation
  and Family History design character.
- Show client identity/provenance, selected record boundary, read/write scopes,
  consent time, expiry, last use, recent safe activity, and status.
- Let the person reduce or revoke a grant with immediate, clearly explained
  effect.
- Explain that Queue context is continuity, not blanket record authority.
- Keep a copyable manual Queue brief as the fallback when no client connects.
- Generate `/ai.txt` tool/scope guidance from the executable contract so names
  cannot drift.
- Add exact client setup steps only after that client passes the complete
  lifecycle; otherwise state the capability requirement only.

## Next safe action

After the grant and result contracts stabilize, design the smallest connection
center around the real grant fields and failure states. Do not create a mock
control whose effect is not enforced by the MCP edge.

## Definition of done

- [ ] A person can understand one connection and its authority without reading
      OAuth or MCP documentation.
- [ ] Scope reduction and revoke change real server behavior, not only UI state.
- [ ] Activity is useful and private-content-safe.
- [ ] Manual Queue handoff remains usable before and after connection failure.
- [ ] `/ai`, `/ai.txt`, tool catalog, scope catalog, and verified-client truth
      are generated or contract-checked for parity.
- [ ] Desktop/phone, keyboard, focus, reduced motion, overflow, empty, error,
      expired, revoked, and stale-tool states pass browser review.

## Evidence

- `app/ai/page.tsx` and `app/ai.txt/route.ts` are the current public setup
  surfaces.
- `components/api/ApiKeyManager.tsx` is evidence of a separate API-key lifecycle,
  not an OAuth connection center.
- `docs/planning/family-history-bring-your-ai-alignment.md` defines the grant,
  connection, and client-truth contract.
