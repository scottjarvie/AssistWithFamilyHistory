## Why this exists

The generated tracker reader is current and visually usable, but its optional
Playwright suite should remain trustworthy as Cards and Work Orders grow. A
hard-coded old count or brittle drag coordinate can turn a correct state update
into noise and hide a real reader regression later.

## Current truth

`pnpm tracker:build`, `pnpm tracker:verify`, and all 48 `pnpm verify` steps pass
for 43 Cards and 11 Work Orders. Manual rendered checks at 1280px and 390px
found the new Cards and AWF-WO-011, zero page-level horizontal overflow, and no
console warnings.

`pnpm tracker:verify-browser` passed four of six scenarios. One assertion still
expects exactly two Work Orders even though the canonical tracker has eleven.
The pointer-drag scenario also did not reorder the first two Backlog Cards in
this content shape; keyboard, touch, stored-order sanitation, filtered order,
and blocked-storage scenarios passed.

## Next safe action

Handle this in a small protected tracker-software tranche: derive expected Work
Order count from canonical source and diagnose the desktop pointer drag with the
current multi-column/card layout. Do not weaken the behavior assertion merely
to make it green, and do not let this displace the proposed MCP/OAuth outcome.

## Constraints

- Test, generator, board behavior, or script changes are software and use a
  normal branch, PR, CI, and deployment path.
- Preserve keyboard and touch reorder behavior, local-only personal ordering,
  canonical Card status, mobile no-overflow, and blocked-storage fallback.

## Evidence

- Failing suite: `tests/e2e/tracker-reader-ordering.spec.ts`.
- 2026-08-16 result: 4 passed, 2 failed; exact output retained in the task
  handoff and `/tmp/dts-tracker-playwright` for this local run.
- Generated-reader manual proof observed 44 Cards, 11 Work Orders, AWF-WO-011,
  AWF-0043, desktop/mobile no-overflow, and no console warnings.

## Definition of done

- [ ] Browser expectations derive current Card/Work Order content rather than a
      historical hard-coded count.
- [ ] Desktop pointer drag reorders inside one lane and refuses cross-lane moves.
- [ ] Keyboard, touch, filter, storage-fallback, detail, and Work Order scenarios
      remain green.
- [ ] `pnpm tracker:verify-browser` and `pnpm verify` both pass.
