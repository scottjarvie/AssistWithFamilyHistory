## Why this exists

Scott (13 October 2026): "we want to store actual data not AI recap of data
alone … we want to store original data so any number of ai can look at that
original data and make their own assessments. Data is king here." Before this,
a source held only a title and a short note, so only an AI's conclusions had a
home.

## Current truth

- `sourceContents`: append-only original content on a source (indexed fields,
  transcription, extract, full text, translation, abstract, and `ai_reading`),
  each saying who made it. Corrections are new rows with `supersedesId`.
- `recordPersonas`: each person exactly as a record names them, with role and
  fields as written. A link to a researched Person is always saved as proposed.
- `sources` gained the record's own date and place, language, citation text,
  image link and external identifiers (FamilySearch ARK, film, memorial).
- `sourceFacts` (Claims) gained `originalText`, `informationKind` and the
  persona they were read from.
- `places` go down to the building (church, temple, cemetery, farm, house,
  school, ship…) with names over time. `topics` hold religions, ceremonies,
  customs, occupations, migrations. `connections` link anything else and start
  proposed.
- MCP: `family_history_save_records` takes places, topics, connections, and
  evidence with contents and personas; `placeCreateKey` works on any place
  reference; new `family_history_add_source_content`; context reads return
  contents, personas, claims and connections.
