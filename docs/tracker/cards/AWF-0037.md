## Why this exists

The product has separately proven an empty signed-in first start, a durable
four-state Queue, and an owner-scoped OAuth MCP workspace. It has not yet proven
the useful joined loop: a newcomer leaves a private research directive, their
chosen AI deliberately claims it, reads only that owner's context, preserves a
sourced result in canonical records, and hands the result back through Queue
into the normal signed-in UI.

## Current truth

Source inspection reproduced one concrete seam before any production fixture
was created. `update_queue` already accepts durable `resultRefs`, but Queue
renders only the result summary and never presents those references. A user can
therefore see **Done** without an actionable route to the person or private
story the AI saved.

The bounded implementation now turns only known signed-in Family History paths
into **Open saved work** links and teaches `update_queue` callers to return those
paths. External, malformed, settings, and opaque legacy references remain
non-clickable. A production-only, user-authenticated acceptance cleanup rail is restricted
to the exact retained non-privileged test subject, exact Convex deployment,
unique `codex-test:awf-joined:` run keys, bounded scans, and an explicit
confirmation phrase and the exact labeled test identity. It refuses cleanup if any unmarked record reuses the
synthetic graph.

Protected review, deployment, and the live disposable workflow remain in
progress. No production family fixture has been created yet.

## Boundaries

- Use only the retained labeled non-privileged test identity and one unique,
  clearly marked synthetic deceased person/evidence/story graph.
- Derive owner identity from the authenticated MCP token; never accept an owner
  supplied by the chosen AI.
- Do not inspect Scott's or another family's records, publish/share a story,
  merge identities, change roles, or change provider defaults.
- Delete the exact Queue, family, MCP receipt/activity, OAuth client, session,
  and local credential artifacts after each live run; retain only the empty
  labeled test identity.
- Treat independent audit and immediate issued-JWT revocation as separate work.

## Definition of done

- [ ] A signed-in newcomer can leave one marked private research directive.
- [ ] A disposable OAuth PKCE chosen-AI client can read the exact owner's brief
      and Queue, claim the directive, and save one citation-backed result.
- [ ] Queue shows the attributable completion and opens the saved person/story
      in the normal signed-in UI at phone and desktop widths.
- [ ] Cross-owner access, arbitrary result-link navigation, and broad cleanup
      fail closed in focused tests.
- [ ] Full verification, a protected PR, exact-main CI, production deployment,
      live public/OAuth boundary checks, and authenticated lifecycle proof pass.
- [ ] Exact fixture/client/session/artifact cleanup returns the labeled test
      identity to an empty private workspace.
